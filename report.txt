SECTION 5 — FEATURE ENGINEERING
================================================================================

Strategy: Three underexploited signal sources were targeted beyond raw audio:
  1. Text in track/album names (genre vocabulary)
  2. Artist identity (genre-consistent by nature)
  3. Audio feature interactions (non-linear genre boundaries)

--- 5.0  Combined DataFrame ---
  - train and test concatenated into all_df for consistent TF-IDF vocabulary
  - _is_train flag added to distinguish the two sets

--- 5.1  TF-IDF on Text Fields ---
  Feature created : text_blob = track_name + ' ' + album_name
  Vectorizer config:
    - max_features   = 100 (top 100 most informative tokens)
    - ngram_range    = (1, 2) (unigrams + bigrams)
    - sublinear_tf   = True (log-scaled TF for better dynamic range)
    - strip_accents  = 'unicode'
    - min_df         = 3 (ignore very rare tokens)
  Output: 100 new columns (tfidf_<token>)
  Rationale: Genre-specific vocabulary like "Symphony", "Drill", "Acoustic Session"
             or bigrams like "death metal", "hip hop" carry strong discriminative signal
             that pure audio features cannot provide.

--- 5.2  Artist Target Encoding ---
  Method : Compute mean of integer-encoded genre label per artist in training rows
  Fitted on: training rows ONLY (leakage prevention)
  Unknown artists (test-only artists): filled with global mean of artist encoding
  Output: 1 new column (artist_genre_mean)
  Rationale: Artists are genre-consistent (Beethoven → classical; Drake → hip-hop).
             This single feature is likely the most predictive in the entire set.

--- 5.3  Derived Audio Features ---
  ┌──────────────────────────┬───────────────────────────────────────────────────┐
  │ Feature                  │ Formula & Rationale                               │
  ├──────────────────────────┼───────────────────────────────────────────────────┤
  │ energy_acoustic_ratio    │ energy / (acousticness + 1e-6)                    │
  │                          │ High → electronic; Low → organic/acoustic         │
  │ dance_energy             │ danceability × energy                             │
  │                          │ High → EDM; Low → classical/folk                  │
  │ mood_index               │ valence × energy                                  │
  │                          │ High → happy/party; Low → ambient/sad             │
  │ speech_music             │ speechiness / (1 - speechiness + 1e-6)            │
  │                          │ Differentiates hip-hop/spoken-word from music     │
  │ loudness_norm            │ loudness + 60   (shifts dB range to ≈ 0..60)      │
  │                          │ More interpretable positive range                 │
  │ duration_min             │ duration_ms / 60,000                              │
  │                          │ Duration in minutes (genre-level signal)          │
  └──────────────────────────┴───────────────────────────────────────────────────┘

--- 5.4  Finalize & Split ---
  - explicit filled with 0 for remaining NaNs, cast to int
  - Combined dataframe split back into train_fe and test_fe via _is_train flag

SECTION 6 — FEATURE SELECTION
================================================================================

Total features after engineering: ~120+ (audio + derived + TF-IDF + encoding)

Selection Oracle: LightGBM (fast, stable importance scores for high-dim data)
  Config: n_estimators=200, num_leaves=63, learning_rate=0.1,
          subsample=0.8, colsample_bytree=0.8, random_state=42

Method:
  - LightGBM fit on full training feature matrix
  - Feature importances extracted (split-count based)
  - Threshold = mean importance across all features
  - Features with importance >= threshold are retained (conservative approach)
  - Bottom half with negligible contribution is discarded

Output:
  - X_sel      : selected training features (shape reported)
  - X_test_sel : selected test features (same columns)
  - Top-40 features plotted in a horizontal bar chart

Rationale for conservative threshold:
  - Prefer retaining borderline features over discarding potentially useful ones
  - Reduces training time and minimises overfitting to noise dimensions

SECTION 7 — MODEL TRAINING & STRATEGY
================================================================================

Cross-Validation Setup:
  - StratifiedKFold: 5 folds, shuffle=True, random_state=42
  - Each fold: ~68K training samples, ~17K validation samples
  - Primary metric: Macro F1 (penalises poor performance on every genre equally)
  - Secondary metric: Accuracy

Evaluation function cv_evaluate():
  - Runs cross_val_score for both accuracy and f1_macro
  - Records mean ± std for each metric
  - Records wall-clock training time

--- Model 1: LightGBM ---
  Hyperparameters:
    n_estimators    = 200
    num_leaves      = 95
    learning_rate   = 0.05
    subsample       = 0.8
    colsample_bytree= 0.8
    reg_alpha       = 0.1
    reg_lambda      = 0.1
    random_state    = 42
  Why chosen: Leaf-wise growth → highest accuracy per iteration; fastest to train.
              May overfit on small datasets but mitigated by L1/L2 regularisation.

--- Model 2: XGBoost ---
  Hyperparameters:
    n_estimators    = 200
    max_depth       = 7
    learning_rate   = 0.05
    subsample       = 0.8
    colsample_bytree= 0.8
    reg_alpha       = 0.1
    reg_lambda      = 1.0
    eval_metric     = 'mlogloss'
    random_state    = 42
  Why chosen: Level-wise growth → more conservative splits; better on noisy labels.
              Slower than LightGBM at this scale.

--- Model 4: Random Forest ---
  Hyperparameters:
    n_estimators    = 400
    max_depth       = None (fully grown)
    min_samples_leaf= 2
    max_features    = 'sqrt'
    random_state    = 42
  Why chosen: Decorrelated ensemble → reduces variance; good reference baseline.
              Hard ceiling below gradient boosters on complex tasks.

Why NOT Neural Networks:
  With 85K samples and ~120 features, GBDTs match or exceed neural network performance
  on structured tabular data while requiring far less hyperparameter tuning and compute.
  GBDTs are the industry standard for structured tabular competitions.

SECTION 11 — CONCLUSION & KEY LEARNINGS
================================================================================

Feature Impact Ranking (estimated order of importance):
  1. Artist Target Encoding      — Most predictive single feature; genre-consistent
                                   by nature (Beethoven → classical, Drake → hip-hop)
  2. TF-IDF Text Features        — Genre-specific vocabulary ("Symphony", "Drill",
                                   "Acoustic Sessions"); bigrams especially powerful
  3. Gradient Boosting > RF      — LightGBM/CatBoost/XGBoost outperform RF by ~2–4%
                                   F1 on 114-class tabular data
  4. Audio Interaction Features  — dance_energy, mood_index, energy_acoustic_ratio
                                   each add marginal but consistent lift
  5. Irreducible Genre Confusion — electronic/electro, hip-hop/rap share near-identical
                                   audio DNA; a data taxonomy issue, not a model failure
